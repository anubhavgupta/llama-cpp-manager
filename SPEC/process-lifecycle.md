## Races that are requirements

- Q23: runningProcess = null runs synchronously right after arming the timer, and the timer callback re-reads the same module-level variable instead of a cap
- Q24: POST /restart answers 200 success:true, but /status settles on running:false: the killed child's close handler clears runningProcess after /restart as
- recorded child launches: 23 across 8 journeys
- exit codes: the exit-code journey records the child argv, the socket events and the manager log; nothing records the signal the manager sent

## Where the recordings are silent

- which signal is sent, and whether a second signal is scheduled: nothing in the recordings observes the manager-to-child signal
- spawn options (cwd, env, detached, stdio pipes) are not recorded; only the program path and its argument vector are
- the manager process own port binding and restart handling are only visible through the recorded HTTP responses
