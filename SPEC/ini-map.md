# ini map — `models-preset.ini` generation

Human view of `SPEC/ini-map.json`, generated by `node tools/parity/spec-reconcile.js`.
Derivation keys: `a` static read of `parity-baseline`, `b` `fixtures/**` recordings, `c` the
independent model pass. Anything that is not a plain agreement carries a `resolution`; the full
matrix is in `SPEC/CONSISTENCY.md`.

- version header: 'version = 1\n\n'
- line format: <key> = <value>, single spaces around =, each line terminated by \n; nothing quoted or escaped
- section order: sections iterate Object.entries(parsed llamaCppConfigs), so localStorage insertion order is the section order (§9 trap 6)
- trailing line after the last section: port — Q10: the last line is "port = <settings.serverPort>" and it is appended after the loop with no section header after it, so the file ends with an orphan key

## Where the recordings are silent

- a section with no stored config behind it is invisible: every recorded section name matches a stored config in the same recording, so nothing shows what happens to an unsaved form
- whether an ini key is emitted when its field holds a retired enum value is not recorded; no recording writes an ini while a control holds a retired value
- the key order inside a section is only observable per recorded document; the three recordings agree but a key that never appears in them has no position
